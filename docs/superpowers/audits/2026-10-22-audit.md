# Qobuz DL2 reliability and performance audit

Date: 2026-10-22. Base commit: `430a7f1ddf267c07779bff7387ac474e9d1305f9`.

## Outcome and scope

The working tree needs integrity and correctness remediation before performance tuning. Five high-priority findings can prevent supported downloads, misreport completion, publish nonaudio data, embed incomplete artwork, or delete files owned by another operation. Seventeen further findings cover incomplete collections, persistent deduplication errors, broken playlist paths, ignored configuration, networking, and avoidable serial execution.

Reviewed all 12 product Python modules, five test files, README, package configuration, lockfile, entry point, and wheel contents. Existing edits to README, CLI, core, downloader, and two untracked tests are part of the audited baseline. No product code, existing tests, configuration, database, or personal downloads were changed. The audit added only this report, the remediation plan, and synthetic evidence. Local `uv sync` created an ignored `.venv` before package downloads failed; it is not a usable locked environment.

Evidence uses real working-tree code, HTTPX MockTransport, temporary files, mocked dependency boundaries where noted, and a fake browser. No live authentication, Qobuz download, account entitlement check, browser login, or real CDN benchmark was performed. Findings describe demonstrated local behavior and source-level risks, not a claim about current Qobuz API responses. Line references below refer to the preserved pre-remediation working tree.

## Findings

Priority: P1 = correctness/integrity failure to fix first; P2 = significant reliability or behavior defect; P3 = narrower hardening issue. Reproducers and captured outputs are in [evidence](2026-10-22/evidence/README.md).

### A01 · P1 · Collection downloads fail at the iterator boundary

Source: `core.py:154`; `qopy.py:190–197`.

Artist, playlist, and label getters are coroutine functions returning an async generator. `handle_url` applies `async for` to the coroutine itself. A real getter produces `TypeError: 'async for' requires an object with __aiter__ method, got coroutine` and an unawaited-coroutine warning before downloading anything. The contract is the same for all three getters.

Use a consistent async-iterator interface and test each collection type through the real getter boundary. Evidence: `core_probe.py`.

### A02 · P1 · Failure and skip paths become successful completion

Source: `downloader.py:281–284, 324–325`; `core.py:117–125`; `cli.py:362–368`.

Tagging exceptions are logged and swallowed. Invalid FLAC therefore returns success from the task aggregate despite no final audio file. Normal returns for ignored singles, unmet quality, samples, and absent download URLs also reach unconditional history insertion. An actual ignored single was recorded in SQLite with an empty output directory; disabling the filter did not allow retry. Core catches download errors without returning a failure outcome; authentication rejection also exits the CLI with code zero.

Introduce explicit completed/skipped/failed outcomes, carry verified artifact paths, record only materialized success, and aggregate failure into a nonzero CLI exit. Evidence: `download_probe.py`, `core_probe.py`, `cli_probe.py`.

### A03 · P1 · Artwork embedding reads an unfinished dependency

Source: `downloader.py:143–177, 236–253`; `metadata.py:69–119, 174–175, 240–241`.

Cover download and audio tagging run concurrently. A gated cover request caused MP3 tagging to fail with `FileNotFoundError` while the release still succeeded. A second gated stream produced a 16,384-byte completed cover but a published ID3 APIC frame containing **zero bytes**, because embedding read the still-buffered file. FLAC also reads the shared cover path and can omit artwork after logging an embedding error.

Await a completed, validated artwork artifact before embedding; make optional-artwork failure policy explicit. Evidence: `download_probe.py`, `artwork_probe.py`.

### A04 · P1 · Nonaudio MP3 responses are published as music

Source: `metadata.py:193–196, 243–244`; `downloader.py:305–307`.

The MP3 tagger checks ID3 metadata rather than MPEG audio. HTTP 200 HTML was given new ID3 tags and renamed to `01. Track.mp3`; a real MP3 parser then raised `HeaderNotFoundError`. Existence alone causes subsequent attempts to skip that corrupt file.

Validate actual media and nonempty output before publication; validate existing artifacts before accepting them. Header parsing catches obvious nonaudio but is not proof of full audio-frame integrity: define a duration/size/frame-validation policy and test truncated payloads explicitly. Evidence: `download_probe.py`.

### A05 · P1 · Temporary and final file ownership is unsafe

Source: `downloader.py:290, 404–408, 434–449`; `cli.py:105–111, 376–378`; `metadata.py:178, 244`.

Extras stream directly to their final filenames. Cancellation after 8,192 of 16,384 cover bytes leaves a partial `cover.jpg`; the next request skips it. `CancelledError` bypasses the `Exception` cleanup. Audio uses predictable `.00.tmp` names, creating collisions across concurrent processes. CLI cleanup recursively deletes **every** `.*.tmp` file under the target; a synthetic `.another-app.tmp` was deleted. This also endangers another downloader's active staging file. Cancellation while executor-based tagging runs needs explicit worker ownership: cancelling an await does not stop a running thread.

Use unique, operation-owned staging files and atomic publication, settle workers before cleanup, and delete only tracked owned files. Evidence: `download_probe.py`, `cli_probe.py`; concurrent-process overwrite risk is source-derived, not a stress-test result.

### A06 · P2 · All but the first collection page are discarded

Source: `core.py:154, 167`; `utils.py:123–124`.

After isolating A01 with a correctly shaped async iterator, two pages yielded only the first ID. Smart discography also reads only page zero. The implementation fetches and retains all pages while failing to use them.

Consume every page, preserve order, bound retention where possible, and apply collection-specific duplicate policy. Evidence: `core_probe.py`. Observable after A01 is repaired.

### A07 · P2 · Global ID history suppresses required artifacts

Source: `db.py:12`; `core.py:95–103`.

History keys contain only ID. The same track requested for a new playlist directory or higher quality is skipped; deleted files also remain marked complete. A synthetic download was called only once across two destinations and two qualities. Track/album identity is not namespaced.

Use artifact identity, destination, actual quality, and filesystem validation. Preserve old history as legacy evidence rather than treating it as proof of present files. Evidence: `core_probe.py`.

### A08 · P2 · Generated playlists contain broken paths and lose ordering

Source: `utils.py:37–73`; `core.py:182–183`.

Root audio becomes `playlist/Root.flac` relative to the playlist itself; nested disc audio becomes `Disc 1/Nested.flac` with its album directory missing. Neither path resolved in the probe. Scanning directories also cannot preserve original playlist order or duplicate occurrences. MP3 detection by substring anywhere in a path can select the wrong parser for FLAC beneath an `.mp3` directory, and broad exception suppression silently drops entries.

Build playlist entries from successful artifact paths in source order, use relative paths from the playlist's directory, inspect actual suffixes, and publish the M3U atomically. Evidence: `core_probe.py`; ordering/suffix issues are source-derived.

### A09 · P2 · Omitted CLI flags override saved true values

Source: `cli.py:201–221, 256–297`.

Click supplies `False` for absent flags; `_build_qobuz` treats any non-None value as an explicit override. With all saved booleans true, every effective boolean reverted to the CLI default and the database was enabled despite `no_database=true`.

Use a real unset state or parameter-source inspection, then test actual CliRunner invocation rather than just `_load_config`. Evidence: `cli_probe.py`.

### A10 · P2 · CLI configuration lifecycle and input validation are incomplete

Source: `cli.py:120–164, 249–254, 313–348, 385–390, 415–429, 452–456`.

`--show-config` alone returns `Missing command` instead of executing; reset and purge share this group lifecycle. Subcommand `--help` invokes configuration bootstrap and can prompt or fetch the web bundle on a fresh install. Malformed INI parsing occurs outside the error handler; invalid booleans raise uncaught `ValueError`. Quality, search type/count, and browser timeout lack appropriate choices/ranges. Invalid numeric configuration can be silently replaced rather than diagnosed.

Make root maintenance actions usable, keep help local and noninteractive, handle read/parse failures uniformly, and validate all effective options before creating clients or directories. Evidence: `cli_probe.py`; numeric consequences are source-derived.

### A11 · P2 · Config writes can destroy settings and expose tokens

Source: `cli.py:51–102, 330–333, 486–491`.

Token refresh rewrites the configuration in place. An injected write error left a previously valid config **zero bytes long**. Under umask 022 a newly written synthetic config was mode 0644. `--show-config` prints the token and app secrets. Token CLI arguments and visible `input()` also permit shell-history or terminal exposure. Read-modify-write has no concurrent-update coordination.

Use atomic same-directory writes, restrictive permissions, and serialized updates; redact secrets in display and provide hidden prompt/stdin token input while retaining any required compatibility. Evidence: `cli_probe.py`; concurrent lost updates and shell history are source-derived risks. No real credentials were read.

### A12 · P2 · Initialization failures leak the HTTP client

Source: `qopy.py:52–65`; `cli.py:232–236, 359–378`.

An authentication failure leaves `AsyncClient.is_closed=False`. The caller only enters its cleanup block after `_build_qobuz` returns, so failed initialization falls outside resource ownership. Cancellation and secret-probe errors need the same handling.

Assign cleanup ownership before initialization and close on all unsuccessful exits. Evidence: `api_probe.py`.

### A13 · P2 · Response parsing bypasses meaningful errors

Source: `qopy.py:90–109, 160–161, 211–227`.

Successful `{}` login data is logged as authenticated with unknown membership; `credential:null` raises `AttributeError`. A non-JSON HTTP 400 from secret validation raises `JSONDecodeError` and prevents trying the next candidate. Response types and refreshed-token type are not checked before state changes.

Validate required schema before side effects, distinguish optional membership from absent identity, and classify HTTP errors independently of JSON body parsing. Evidence: `api_probe.py`. Do not infer current entitlement policy from these malformed fixtures.

### A14 · P2 · Retry policy misses transient APIs and retries permanent downloads

Source: `qopy.py:156–164`; `bundle.py:31–44`; `downloader.py:411–425`.

API GET 503 and read timeout fail after one attempt even when a subsequent success is queued. The downloader retries every HTTP error, including permanent status errors, with deterministic backoff; it ignores Retry-After. Whole-file attempts restart from zero. This adds avoidable latency and bytes while leaving metadata operations fragile.

Centralize bounded, status-aware GET retries with jitter and Retry-After; avoid blind replay of login POST and fatal auth/quality errors. Add resumability only with validator/range checks and evidence that it is worthwhile. Evidence: `api_probe.py`; permanent-status retry and full restart follow directly from code.

### A15 · P2 · Compressed transport lengths are checked against decoded bytes

Source: `downloader.py:431–441`.

`Content-Length` describes encoded transfer data while `aiter_bytes()` yields decoded data. A complete 64-byte gzip body expanding to 32,768 bytes failed all three attempts and was deleted.

Define representation-aware integrity checks; preserve detection of truncated unencoded transfers. Evidence: `download_probe.py`. Actual Qobuz audio compression behavior was not measured.

### A16 · P2 · Discography ranking can eliminate every eligible album

Source: `utils.py:132–158`.

Maximum quality and remaster presence are computed before excluding other artists or unwanted editions. Three cases returned no album: another artist's higher-quality release, a lower-quality remaster alongside a higher-quality original, and a higher-quality deluxe edition with extras disabled.

Filter eligibility first, then rank with an explicit consistent edition/quality policy. Evidence: `core_probe.py`.

### A17 · P2 · URL matching accepts foreign hosts and partial IDs

Source: `utils.py:182–189`; `core.py:193–200`.

The unanchored optional-host regex accepts `https://example.com/album/123` and `xxx /track/123`, and truncates `abc-123` to `abc`. Last.fm routing similarly checks for a substring anywhere in input.

Parse origin and complete path structure; preserve intentionally supported relative URLs and reject ambiguous IDs instead of silently selecting another resource. Evidence: `core_probe.py`. Foreign-host acceptance here parses an ID; it does not itself fetch that foreign host.

### A18 · P2 · SQLite connections and failures lack explicit lifecycle

Source: `db.py:9–16, 23–39`.

SQLite's connection context manager handles transactions without closing the connection. With GC disabled, 100 lookups grew descriptor count from 5 to 105; collection reduced it to 4. Broad `OperationalError` suppression during creation also treats real schema/storage errors like an existing table, while insert failures only log.

Close deterministically or give one connection a defined lifecycle, use explicit schema existence/migrations, and surface write failures through the result model. Evidence: `core_probe.py`; error classification follows from code.

### A19 · P2 · Album quality enforcement checks only the first track

Source: `downloader.py:119–128, 190–207, 374–391`.

`--no-fallback` examines the first track for album-level naming/quality but `_process_track` ignores downgrade restrictions on later tracks. A synthetic downgraded 16-bit track was passed to download despite quality 27 and fallback disabled.

Apply the quality policy to every file URL and report mixed-quality/skipped outcomes honestly. Evidence: `quality_probe.py`.

### A20 · P2 · Playlist tracks bypass useful concurrency

Source: `core.py:176–181, 384–389`; `downloader.py:89–103, 210–253`.

Collections and Last.fm await one `download_from_id` at a time. A playlist of individual tracks therefore uses one audio transfer at a time regardless of a configured limit of eight; each creates a new download HTTP pool. A synthetic eight-item playlist reached peak concurrency **1** with limit 8. This is downstream of A01 and isolated using an appropriate iterator.

Use a shared operation-level transfer budget and reusable HTTP pool. Do not merely gather multiple albums, which would multiply their separate semaphore limits. Bound scheduled tasks and API pressure. Evidence: `collection_benchmark.py`; real network speedup remains unmeasured.

### A21 · P3 · Bundle extraction accepts incomplete empty secrets

Source: `bundle.py:65–81`; `tests/test_bundle.py`.

Two seed entries with missing info/extras return two empty strings rather than an extraction error. Tests only match regex fragments and do not exercise full extraction. Validate complete components and decoded nonempty values; retain a full valid synthetic fixture and malformed variants. Evidence: `api_probe.py`.

### A22 · P3 · Browser token capture accepts unrelated failed responses

Source: `browser_login.py:46–54`.

Matching requires only POST and the substring `user/login` anywhere in URL. Fake Playwright delivered a third-party HTTP 500 response whose query included that substring; its synthetic token was returned. This is a demonstrated missing validation boundary, not a demonstrated real-world exploit.

Require the intended API origin/path, successful status, and nonempty string token. Add timeout/closed-window tests without launching a browser. Evidence: `browser_probe.py`.

## Performance interpretation

The 64 MiB in-memory MockTransport benchmark initially measured median 0.04441 seconds with current 8 KiB chunks and Rich updates, versus 0.04148 seconds with a 256 KiB comparison loop. That is not a real CDN measurement, and the small difference does not establish a material chunk-size problem. Captured rerun results are in the evidence output.

Prioritize avoiding false skips, needless permanent-error retries, all-page buffering, serial playlist transfers, per-track pool creation, and whole-file restart costs. Measure network bytes, requests, connection count, time to first completed track, throughput, event-loop responsiveness, memory, and cancellation latency before changing defaults. Keep the existing conservative default limit of **2** until target-network evidence supports another value.

Other minor issues: 25-hour durations wrap to `01:00:00`; missing/nullable metadata can trigger uncaught errors in tagging and formatting; custom filename collisions and corrupt existing files lack a validation policy; recursively included URL text files have no cycle guard. These belong in the relevant boundary tests during remediation, not in an unrelated rewrite. No claim of exhaustive external API coverage, full audio-frame validation, dependency vulnerability clearance, or Windows runtime qualification is made.

## Remediation order and acceptance

1. Establish truthful result propagation and repair collection iteration.
2. Make media/extra staging, validation, artwork dependencies, and cancellation safe.
3. Repair all-page collection handling, artifact history, and playlist generation.
4. Repair CLI/config lifecycle and API/auth/error boundaries.
5. Introduce measured global concurrency and lifecycle improvements; add repeatable CI qualification.

The executable task breakdown is in [the remediation plan](../plans/2026-10-22-qobuz-remediation.md). Implementation has not started. Product/test/README/manifest hashes must still match the pre-audit inventory when this audit is delivered. Existing history and audio must remain preserved during later migrations; legacy history alone cannot establish file validity.
